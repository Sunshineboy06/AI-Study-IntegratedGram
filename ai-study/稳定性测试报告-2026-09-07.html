五、发现的问题与建议

高 · 环境问题端口重复绑定：8796 / 8797 被历史残留实例占用

Windows 下 werkzeug 允许多进程绑定同一端口（SO_REUSEADDR 语义），导致新旧实例共存、请求被路由到旧版本服务（实测 /api/config 返回了旧版含 API Key 配置的响应）。

占用进程：PID 24368（pythonw3.13.exe，监听 8796）、PID 36660（python.exe，监听 8797），另有 PID 34492 疑似残留。

影响：访客可能拿到旧版页面/接口；且旧配置接口暴露 API Key 状态。建议：确认后终止这三个残留进程；部署时在启动脚本中加入端口占用预检（如 netstat 检测或先 bind 失败即退出）。Linux 上 gunicorn 默认不允许重复绑定，此问题主要是 Windows 本机风险。

中 · 一致性.csv / .json 支持承诺与实现不符

server.py 的 ALLOWED_EXT 与 400 文案均包含 .csv/.json，但 parsers.py 不支持，上传会得到前后矛盾的报错。建议二者对齐：要么 parsers 增加透传文本的 csv/json 分支，要么从白名单与文案中移除。

低 · 体验直连 werkzeug 时超限上传表现为连接重置

MAX_CONTENT_LENGTH 生效但客户端收到的是连接中止而非 413。公网部署（nginx 反代）会由 nginx 干净地返回 413，可接受；如需直连场景友好，可在 nginx 配置 client_max_body_size 100m; 与对应错误页。
